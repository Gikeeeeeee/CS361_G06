# Smart Faculty Navigator

## Project Vision

Smart Faculty Navigator เป็นระบบกลางที่ช่วยให้บุคลากรและนักศึกษาภายในคณะสามารถตอบคำถามว่า **“ต้องไปที่ไหน เมื่อไร และไปอย่างไร”** โดยเริ่มต้นจากการให้บริการข้อมูลสถานที่ (Information Service) และสามารถต่อยอดไปสู่ข้อมูลตารางเรียน ตารางสอบ กิจกรรม การค้นหาตามวัตถุประสงค์ ระบบนำทาง และการเชื่อมต่อกับปฏิทินส่วนตัวในอนาคต

## Primary User

กลุ่มผู้ใช้งานหลักคือ **บุคคลภายในคณะ** ได้แก่ นักศึกษา อาจารย์ และเจ้าหน้าที่ ซึ่งอาจต้องเดินทางไปยังห้องหรือจุดบริการที่ไม่คุ้นเคย

ใน V1 ระบบยังไม่มี Authentication ดังนั้นผู้ใช้ทั้งสามกลุ่มจะถูกจัดอยู่ในกลุ่มเดียวกัน เนื่องจากมีความต้องการหลักร่วมกัน คือการเข้าถึงข้อมูลสถานที่ในรูปแบบ Read-Only โดยระบบยังมุ่งช่วยเหลือผู้มาใหม่หรือผู้ที่ไม่สะดวกสอบถามข้อมูลจากผู้อื่นโดยตรง

สำหรับ V1 จะยังไม่ครอบคลุมบุคคลภายนอก เพื่อจำกัดขอบเขตของข้อมูลที่ต้องจัดเก็บและเผยแพร่

## Problem

ปัจจุบัน เมื่อบุคคลภายในไม่ทราบว่าห้องหรือจุดบริการอยู่ที่ใด มักต้องสอบถามเจ้าหน้าที่หรือเพื่อน ดูผังอาคารที่ติดตั้งอยู่ภายในอาคาร หรือเดินค้นหาด้วยตนเอง ซึ่งทำให้ต้องเสียเวลาและไม่สามารถวางแผนการเดินทางล่วงหน้าได้อย่างมีประสิทธิภาพ

### Problem Statement

บุคคลภายในคณะไม่สามารถเข้าถึงข้อมูลเกี่ยวกับตำแหน่งของห้องหรือจุดบริการ รวมถึงสิ่งอำนวยความสะดวกภายในสถานที่ได้ล่วงหน้า ทำให้ต้องพึ่งพาการสอบถามผู้อื่นหรือค้นหาสถานที่ด้วยตนเองเมื่อเดินทางมาถึง

### Desired Outcome

ระบบควรช่วยให้ผู้ใช้สามารถค้นหาข้อมูลอาคาร ห้อง และจุดบริการได้ด้วยตนเองตลอดเวลา รวมถึงสามารถเตรียมตัวและวางแผนล่วงหน้าได้ เช่น ทราบว่าห้องมีเครื่องปรับอากาศ มีห้องคอมพิวเตอร์ หรือมีสิ่งอำนวยความสะดวกใดบ้าง

นอกจากนี้ยังช่วยลดภาระของเจ้าหน้าที่ในการตอบคำถามเกี่ยวกับตำแหน่งห้องซ้ำ ๆ

## V1 Goal

V1 มุ่งให้บริการข้อมูลสถานที่และจุดบริการในรูปแบบ **Read-Only โดยไม่ต้องเข้าสู่ระบบ** โดยจำกัดพื้นที่เฉพาะ **อาคาร บร.3 และ บร.4** เพื่อให้ผู้ใช้สามารถค้นหาและทำความเข้าใจตำแหน่งของจุดหมายได้ก่อนเดินทางไปถึง

ระบบรองรับการใช้งาน **2 ภาษา (TH / EN)** และเน้นข้อมูลแบบ Static Information ที่ผ่านการตรวจสอบและมีความแม่นยำสูง

## V1 In Scope

ขอบเขตของระบบใน V1 ครอบคลุมข้อมูลหลัก ได้แก่

- **Building Name** — ชื่ออาคาร โดยเน้นอาคาร บร.3 และ บร.4
- **Room Name** — ชื่อและรหัสห้อง เช่น `บร.3-121`
- **Room Feature** — รายละเอียดภายในห้อง เช่น เครื่องปรับอากาศ ห้องคอมพิวเตอร์ และจำนวนที่นั่ง
- **Building Facility** — จุดอำนวยความสะดวก เช่น ห้องน้ำ จุดกดน้ำ และลิฟต์
- **Building Plan** — ผังอาคารและผังแสดงพื้นที่ในแต่ละชั้น
- **Room Image** — ภาพถ่ายบรรยากาศหรือรูปหน้าห้อง

## V1 Out of Scope

V1 จะยังไม่ครอบคลุมระบบ Review / Rating, ข้อมูลกิจกรรม ตารางสอบ หรือตารางเรียน รวมถึงระบบสมาชิก Authentication และ Role Management

นอกจากนี้ยังไม่รวมระบบนำทางแบบ Turn-by-Turn, Real-time Indoor Positioning, Calendar Export และ Back-office สำหรับให้เจ้าหน้าที่แก้ไขข้อมูลผ่านระบบ โดยในระยะแรกทีมงานจะนำเข้าข้อมูลแบบ Manual

พื้นที่นอกเหนือจากอาคาร **บร.3 และ บร.4** ก็ยังไม่อยู่ในขอบเขตของ V1

## External Actors / Systems

แหล่งข้อมูลหลักมาจาก **ผู้ดูแลอาคาร สำนักทรัพย์สิน กองบริหารงานอาคาร กองกิจการนักศึกษา และคณะวิทยาศาสตร์** ซึ่งเป็นหน่วยงานที่เกี่ยวข้องกับการดูแลอาคาร บร.1–บร.4

ในด้านแผนที่ ระบบสามารถเชื่อมต่อกับบริการภายนอก เช่น **AWS Location Service หรือ Google Maps API**

ทีมพัฒนาจะทำหน้าที่เป็น Data Consumer โดยรวบรวม ตรวจสอบ และนำข้อมูลจากแหล่งข้อมูลต้นทางเข้าสู่ระบบ

## Open Questions / To Validate

### 1. User Validation

นักศึกษา อาจารย์ และเจ้าหน้าที่ประสบปัญหาในการค้นหาสถานที่ในระดับใกล้เคียงกันหรือไม่ หรือกลุ่มอาจารย์และเจ้าหน้าที่มีความคุ้นเคยกับพื้นที่อยู่แล้ว

### 2. Data Owner

ใครคือเจ้าของข้อมูลอาคาร บร.3–บร.4 ที่มีอำนาจในการอนุมัติและรับรองความถูกต้องของข้อมูล

### 3. Data Format

เจ้าหน้าที่มีข้อมูลต้นทางในรูปแบบใด เช่น PDF, Excel, CAD หรือรูปภาพ และสามารถส่งมอบข้อมูลให้ทีมพัฒนาได้เมื่อใด

### 4. Data Collection Effort

หากไม่มีข้อมูลต้นทาง ทีมพัฒนาจำเป็นต้องลงพื้นที่สำรวจเองมากน้อยเพียงใด และต้องใช้เวลาและทรัพยากรเท่าใดในการจัดทำข้อมูล

### 5. Information Priority

ข้อมูลประเภทใดมีความสำคัญต่อผู้ใช้มากที่สุด เช่น ตำแหน่งห้อง สิ่งอำนวยความสะดวก หรือรูปถ่ายห้อง เพื่อใช้กำหนดลำดับความสำคัญของฟีเจอร์ใน V1

### 6. Data Sensitivity

ผังอาคารมีพื้นที่หรือข้อมูลใดที่ไม่ควรเปิดเผยหรือไม่ เช่น ห้องเซิร์ฟเวอร์ ห้องเก็บสารเคมี หรือพื้นที่ที่มีข้อจำกัดในการเข้าถึง

### 7. Data Change Frequency

ข้อมูลสถานที่และผังห้องมีการเปลี่ยนแปลงบ่อยเพียงใด และควรมีกระบวนการตรวจสอบหรืออัปเดตข้อมูลบ่อยแค่ไหน
